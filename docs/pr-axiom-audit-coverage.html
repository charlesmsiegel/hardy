What this actually changes

Three commands could report a Lean proof as verified. Only one of them checked what the proof stood on. hardy batch appended #print axioms to its final check and then graded on Lean's process exit status — nothing parsed the report, and the field named axioms in result.json held the whole Lean stdout blob. A proof resting on sorryAx, or on an axiom reached through an import, was written up as kernel verified. That is what this change ends.

A new hardy.audit parses the report and grades it; batch, chat, and the staged prove verifier all now go through it. Unattended runs fail closed on anything beyond Lean's three axioms. The interactive session gains an audit it never had at all: after the staged tree builds and before anything is committed, Lean is asked what every theorem and lemma in the rebuilt modules depends on, and the save is refused whole on a hole or an unapproved assumption.

Separately, the test suite gains coverage measurement: pytest --cov, a floor, a CI job that runs the hermetic suite on every pull request, and a kept artifact.

Beyond what the issue asked for

Three things the issue did not name, each disclosed rather than slipped in:

  • A latent verifier bug. src/hardy/verifier.py's private matcher used \btheorem_name\b; the trailing apostrophe in add_comm' is not a word character, so every primed declaration the kernel accepted was refused for emitting no axiom report. Fixed by the unification, with a regression test.
  • Universe binders and Unicode. The batch name derivation split on (, {, and :, turning theorem Foo.{u} … into Foo., and its identifier pattern was ASCII-only. src/hardy/lean.py:33.
  • CI ran the suite behind a path filter. A change to the verifier or the runner could reach main with nothing having run it. .github/workflows/tests.yml runs it unconditionally; the duplicated job leaves cas-backends.yml.

Classification: mixed, deliberately — two concerns, cleanly separated by file

Axiom audit (feature + latent bugfix): src/hardy/audit.py, src/hardy/lean.py, src/hardy/runner.py, src/hardy/chat.py, src/hardy/verifier.py, src/hardy/models.py, both prompt templates, and the four documents. Coverage (tooling): pyproject.toml, .gitignore, both workflow files, uv.lock. What did not change, where a reader might expect it to.
  • No at-audit approval prompt. The repo's own spec (docs/superpowers/specs/2026-07-24-axiom-audit-gate-design.md) designs an interactive prompt that asks the human about an axiom the audit discovers, showing the statement Lean reports. This change fails closed instead: the save is refused, the axiom is named, and the model routes through the existing request_assumption. Ergonomics, not soundness — recorded in the plan's status note rather than left implied.
  • save_latex does not require disclosure. A workspace verified only modulo an approved assumption can still be written up without naming it. The spec calls for a gate here; it is not built, and is listed as still open.
  • No approved-statement drift detection. A name approved once stays approved even if a Mathlib upgrade makes it resolve to a different statement.
  • No TerminalReason member for the batch refusal. axioms_rejected is batch's own reason string; prove keeps UNEXPECTED_AXIOM for both a hole and an assumption, deliberately, because that value is written to disk and read by things that never import Hardy.

Flow 1 — hardy batch accepts a proof

The change inserts one decision between "Lean exited 0" and "kernel verified". Everything before it is unchanged.

Before

sequenceDiagram

  participant R as runner.dispatch
  participant L as Lean
  M->>R: submit_proof(proof)
  R->>L: elaborate + "#print axioms T"
  L-->>R: exit 0, report printed
  Note over R: report never read
  R->>R: found = result
  R-->>M: ok
  Note over R: formalization = "kernel verified"
axioms = raw stdout blob

After

sequenceDiagram
  participant M as Model
  participant R as runner.dispatch
  participant L as Lean
  participant A as hardy.audit
  M->>R: submit_proof(proof)
  R->>L: elaborate + "#print axioms T"
  L-->>R: exit 0, report printed
  R->>A: parse(result.report, name)
  alt no name, or no single readable report
    A-->>R: None
    R-->>M: refused, reason recorded
  else verdict not clean
    A-->>R: forbidden / unapproved
    R-->>M: refused, verdict recorded
  else clean
    A-->>R: verdict
    R->>R: found = result, verdict
    R-->>M: ok
  end

What moved

  • New gate between elaboration and acceptance — src/hardy/runner.py:40. It reads result.report, not result.output: the latter is cut to its trailing 12 000 characters for the model, and grading on that would refuse a proof whose report was merely truncated (src/hardy/lean.py:110).
  • New terminal reason axioms_rejected, reached only when a submission elaborated and was then refused — src/hardy/runner.py:146. It does not swallow "nothing was submitted", and wall_clock_limit / turn_limit / runtime_error still take precedence.
  • Changed record shape. RunResult.axioms goes from str to dict — src/hardy/models.py:66. It now distinguishes three facts the blob collapsed: a verdict, an audit attempted but not established, and no submission having reached the audit.
  • Ordering is unchanged around the wall-clock deadline: the audit runs inside the submit_proof branch, and late is still computed after it, so a proof that finished inside the budget still counts and one that did not still does not.

Flow 2 — hardy chat saves a Lean file

The audit is the last gate before commit(), so a refusal leaves the workspace byte-identical.

flowchart TB

  B --> C["_final_gates: holes, declared axioms"]

  D --> E["build module + every dependent"]
  E --> F["registered names still resolve"]
  F --> G["NEW: _audit_tree over the built shadow"]

What moved

  • One extra Lean run per save — src/hardy/chat.py:549. It imports the oleans the shadow build just produced rather than re-elaborating their source, but it is a real cost, and the test that pinned "one compile, zero extra elaborations" is updated to "one compile, one audit" rather than deleted (tests/test_chat_workspace.py:147).
  • Scope is the rebuilt set, not the edited file — src/hardy/chat.py:520. A dependent inherits whatever the edit brought in, so editing a helper re-audits every theorem above it. This is the case the tests exercise at tests/test_chat_audit.py:111.
  • The verdict is published after the write, not before — src/hardy/chat.py:494. A record stored first would survive a failed commit and describe a tree that never existed.
  • Records are per module, so a scaffolding save elsewhere cannot erase what an earlier save established, and delete_file drops the record with the module (src/hardy/chat.py:846).
  • check_lean is untouched. Scratch work is where a model finds out what an axiom would cost it, so it is not gated.

Verdict: mergeable. No must-fix found; four should-fix items, all of them scope boundaries the change states rather than hides.

The core claim holds: a batch proof can no longer be graded kernel verified without an audited axiom set, and every uncertainty refuses. The riskiest thing here is not the audit — it is that the audit is now a gate, so a false refusal is a new way for Hardy to stop working. Invariant impact

  • Strengthened, and this is the point: "only Lean kernel acceptance justifies verified" was enforced on one surface and is now enforced on three, through one parser and one allowlist (src/hardy/audit.py:22). verifier.ALLOWED_AXIOMS is kept as an alias of audit.STANDARD so the two cannot drift apart.
  • New invariant to maintain: every name Hardy interpolates into #print axioms must be a name Lean will accept. Two places produce one — LeanTools.target_name from a frozen request, and workspace.declarations from a saved source. They use different patterns (src/hardy/lean.py:33 refuses guillemets; src/hardy/workspace.py:35 allows them). That is intentional — a request's declaration head and a saved file's declarations are different inputs — but it is now a coupling nothing type-checks, and the guillemet case is only covered by tests/test_chat_audit.py:207.
  • Weakened nowhere. No existing gate was relaxed. _final_gates' textual axiom check is kept as a cheap pre-check rather than replaced, which is the right order: it costs nothing and the audit costs a Lean run.
  • New failure mode: "the audit could not be established" now refuses saves and submissions that previously succeeded. Every path that produces it is tested (tests/test_hardy.py:297, tests/test_chat_audit.py:150), and all of them are genuine uncertainty — but a Lean version that changes the report's wording would brick both surfaces until the parser was updated. That is the intended trade (fail closed), and it is worth stating in the PR body so nobody is surprised by it in the field.
