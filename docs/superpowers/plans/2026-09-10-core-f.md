# Core F and supporting comparison work

The roadmap is the approved design. Core D landed after its full hermetic gate;
all Core E work remains deferred by user instruction. Use the existing frozen
ProofTask, formal verifier, run storage and provider operations. A strategy's
ranking, summary or submitted proof never grants formal authority.

## Implementation sequence

- [x] F0: add a synchronized run-owned check/deadline budget and a ranked,
  deduplicated frontier of exact proof candidates with retained Lean feedback.
  Keep source-linked trajectories and independently verify candidate success.
  Existing iterative/sketch and tool operations can share the same budget.
- [x] X1: add a read-only comparison primitive over authenticated scoreboards,
  explicit treatment differences, paired rows and honest measurement coverage.
  Preserve unmatched/invalid rows and separate proof from canonical review cost.
- [x] F1: race independent attempt contexts with branch-local cancellation,
  separate artifact stores, shared ceilings and a canonical final verification.
  Drain losers and report all attempt costs, including missing usage coverage.
- [x] F2: compose working strategies under the same budget, with explicit
  no-progress escalation and cheap work near exhaustion; retain partial output.
- [x] F3: derive source-linked tried/Lean-response/do-not-repeat notes from
  failed strategy trajectories; compare compact and full-history conditions.

The frontier is over textual Lean proof candidates and observations, not saved
Lean elaborator metavariable states. Runtime owners retain cancellation and
per-process limits for operations already in flight. Shared ceilings do not
claim token/cost enforcement, which belongs to X5. Deterministic comparisons
validate accounting and controls; live performance requires separately recorded
contemporaneous trials and is never inferred from scripted model fixtures.
