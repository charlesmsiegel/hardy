# Core B: persistent mathematical project

> **For agentic workers:** Use superpowers:executing-plans task by task; independent graph and policy work may use superpowers:dispatching-parallel-agents.

**Goal:** Implement roadmap B0–B5 as reusable project operations, with restart and deterministic acceptance fixtures.

**Spec:** Core B in `docs/roadmap.md` and sections 3–7, 15 and 18 of `docs/research-architecture.md`.

**Architecture:** An append-only sequence of atomic transaction files stores immutable A0 records. Pure snapshots feed graph queries, policy and views. Context and representation workflows compose these operations; only authenticated capability readers can support acceptance.

**Tech stack:** Python 3.11+, existing Pydantic frozen values, filesystem guards and OS file locks, pytest. No added dependencies.

## Global constraints and rulings

- Work on the code side (`main`) as required by AGENTS.md; no corpus content changes.
- The user's request starts Core B and supersedes the former Core A stopping point. Core C and UI workflow integration remain later work.
- Preserve A0 record identities and schema; proposals and research status are not proof.
- Context ancestry preserves local assumptions; weaker-context claims require explicit discharge/transport evidence.
- No execution isolation or live model/Lean validation is claimed by hermetic tests.
- Use a guarded project `ledger/` directory, separate from `session.json`. Each committed transaction is one atomically replaced, fsynced file under a serialized writer lock; incomplete temporary files are not events. Refuse gaps, corrupt events and unknown schemas.
- Reuse capability readers via injected named operations. A caller-created acceptance artifact is not authority; policy validates exact evidence and decisions on use.
- The roadmap already supplies the architectural design authorized by this request. Routine implementation choices are recorded here rather than asking for renewed approval.

## Shared interfaces

`ledger/state.py` exposes frozen `LedgerSnapshot(records: tuple[LedgerRecord, ...] = (), revision: int = 0, active_context: VersionRef | None = None)` with `get(ref)`, `head(id)` and `current(record_type)`; exact lookup raises `ValueError` when missing. Records retain all versions, while `current` returns the last version per stable ID. `ledger/store.py` exposes `LedgerStore(project: Path).read()` and `.append(records, *, expected_revision, activate=None, validate=None)`. A validator consumes `(before, after)` under the writer lock. No validator means proposals only: accepted resolutions and trust-scope replacements are refused.
