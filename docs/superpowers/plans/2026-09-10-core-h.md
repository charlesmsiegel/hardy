# Core H implementation plan

The approved roadmap calls for durable reuse over the existing ledger and Lean
artifacts. Core E remains deferred. Work starts independently from the verified
Core F base; integrate Core G before H's final frozen-source test gate.

- [x] H0: derive a rebuildable, content-identified index from explicit project
  and shared-library snapshots. Keep formal results, approved assumptions,
  semantics, goals and approaches separate. Rank exact IDs and scoped aliases
  first; authenticate current scope, context, evidence and environment at use.
  Missing or unreadable sources and rejected candidates remain visible.
- [x] H1: run deterministic retrieval-off/on reuse fixtures after restart for
  lemmas, concepts, representations, contexts, goals and blocked approaches.
  Report discovery, delivered provenance and rejection behavior. Decide whether
  any measured residual category needs another store; do not infer model gains.
- [x] H2: bind declared retrieval sources, frozen index, split plan and exposure
  records into evaluation identity and audit. Separate exact repeat, related
  transfer, declared-local held-out and unknown coverage. Missing sources and
  incomplete exposure cannot establish held-out performance. Freeze retrieval
  across rows so earlier outputs cannot leak into later rows.

Each item gets a tested commit. Review exact-reference, revocation, shadowing,
scope and artifact-tampering cases. Run repository Ruff, the complete hermetic
coverage gate and installed-wheel checks before landing. Keep the TODO index,
roadmap and four project overview documents consistent.
