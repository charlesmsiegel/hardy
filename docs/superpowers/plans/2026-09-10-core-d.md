## Design

Research, Explore, Critique, Repair, Referee and publication are different
operations over the same exact mathematical history. They compose the existing
context, representation, acquisition, policy and capability owners. A workflow
cannot turn a model judgment or recorded status into formal authority. External
contracts, local hypotheses, partial coverage and failed approaches stay visible.

Use immutable requests/results and named capability operations with snapshots;
never pass a whole interactive session. Keep semantic proposals outside atomic
ledger writes, reject stale callbacks, and retain the original claim on repair.
Documents receive selected mechanical content rather than graph access.

## Verification and landing

- Test each item before its commit, including actual existing-owner composition
  and adversarial stale/authority/history cases. Run scoped Ruff.
- Review concrete inputs across workflow seams, with tested corrective commits.
- Update README, DESIGN, FEATURES, ARCHITECTURE, roadmap and TODO together.
- Freeze source for the complete hermetic suite with coverage:
  `uv run --extra test pytest -q -m 'not real_toolchain and not live' --cov`.
  A configured machine has real-toolchain tests; do not accidentally run a corpus
  sweep. Keep the coverage floor and skip rules unchanged.
- Require clean full tests and repository Ruff before landing. Build and run the
  installed-wheel smoke check when final integration changes packaging seams.
- Fast-forward only the verified tree to main, then continue eligible Core F-I
  and independent lanes. Skip every Core E item pending human input, as directed.
