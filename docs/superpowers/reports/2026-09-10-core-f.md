## Reviewed behavior and limits

Best-first records exact proof sources, heuristic rank and parent observations.
Candidate limits do not discard queued work. Strategies and model-facing Lean
checks share atomic allocation and one deadline; reserved views preserve final
checks. Actual iterative/sketch/tool composition has deterministic tests.

Race tests use independent attempt contexts and real iterative strategies,
synchronized starts, branch-local cancellation and late usage. A fast unverified
submission cannot beat a verified proof. Failed provider opening remains an
unknown accounting slot, and malformed usage cannot discard a verified result.

Escalation tests move from iterative to ranked search with the same task and
budget, prefer configured cheap work near exhaustion and retain partials. Review
caught a local stage cutoff incorrectly stopping the whole run; the regression
now advances when global budget remains. Runtime errors retain type and message.

Staged integration preserves canonical formal artifacts, starts the proof clock
after faithfulness approval and binds Claude's tools/retriever across proof
threads. Codex's separate MCP process has no shared owner bridge; best-first is
refused there. Legacy iterative availability does not imply shared MCP budgeting.
Race and escalation are shared APIs requiring configured runtime operations.

Compact versus replay-full both open a fresh provider context per expansion,
reuse the same tool/budget owner and select the same source-bound failed
attempts. Native full history remains the default. Tampered replay is refused
before opening the next context. A reviewed slow-context setup case now checks
the deadline again before sending a provider request.

Independent verifier calls have a prospective journal separate from model tool
calls. A verifier invocation can reject before running Lean; neither count is a
claim of total Lean processes or CPU. Legacy missing call journals stay unknown.

X1 audits existing boards before admitting outcomes/usage. Corruption, duplicate
slots, unmatched runs and partial reports remain visible. Canonical reader spend
is separate and a lower bound when requested exchanges are not fully recorded.
Source/host/treatment identities are recorded provenance, not independent causal
attestation. No old scoreboard is restamped to become comparable.

Actual scripted staged runs compare iterative with best-first, and full replay
with compact replay, over the same frozen claim and environment. Each pair
passes recorded-artifact and canonical-read audits. Review caught an omitted
reader-model control; reviewer configuration/template now enter the run/todo
key and comparison, alongside context policy and shared-tool budgeting. A
different canonical reader cannot masquerade as a history-only treatment.

Model and Lean judgments in the hermetic fixtures are scripted. These tests do
not establish performance gains, process isolation, live-paper acceptance or
fixed token/cost budgets. In-flight timeout/cancellation remains runtime-owned.
