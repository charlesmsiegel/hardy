The complete design map

Hardy

A model-agnostic theorem-proving harness where language models propose, Lean verifies, and the harness preserves an honest account of what succeeded.

Interactive experiment implemented. Running hardy opens a durable mathematical conversation backed by direct Lean and LaTeX tools, a linked naming manifest, and explicit human approval for assumptions. The old sandbox remains absent; use only trusted output in a disposable environment. A real model + pinned toolchain acceptance run is still outstanding.

The core loop

1 · RequestAn informal claim, Lean theorem, or proof to inspect.
2 · OrchestrateChoose a workflow and strategy; enforce budgets and stopping rules.
3 · ExperimentThe model calls narrow tools and revises from structured Lean feedback.
4 · Verify & reportThe kernel checks formal work; Hardy saves artifacts, grades, and trajectory.

System layers

Workflow & strategy

Phases, retries, budgets, fixed points, and pluggable search from iterative repair to parallel attempts.

Model runtime

Claude through the Claude Code agent SDK, authenticated by subscription rather than an API key. Hardy's tools run in-process, so the harness still performs every check and write, but the SDK owns the turn loop — see issue #23. /model switches models without losing the provider thread.

Tool layer

Bounded verbs for Lean, goals, lemmas, holes, papers, citations, and writeups.

Lean interaction

Direct invocation first; later persistent sessions, pools, snapshots, and cheap automation.

Computer algebra

A persistent kernel — SymPy by default, Singular or Macaulay2 when configured — so the model can compute before it guesses. Replay rebuilds state after a kernel dies and checks that an exported script and notebook reproduce the session; the script is then run as a subprocess, because replaying cells is not evidence about the file. No computation is evidence: the verifier never reads any of it.

Knowledge

Versioned literature, premise retrieval, assumed-paper libraries, and contamination-aware memory.

Evidence

Trajectories, anti-cheat audits, immutable provenance, fixed benchmarks, and equal-budget comparisons.

Environment

One installer per OS takes a clean Linux, macOS, or Windows machine to a working hardy: Python, lake via elan, a shared Mathlib project, pdflatex, and a config file that hardy doctor then verifies. WSL is never required.

Terminal (hardy.tui)

On a TTY, a real prompt_toolkit shell: ghost-text command completion, a /model selector, and Esc that stops waiting on a turn without cancelling it. Falls back to a line-based session with the same commands — no TTY, --plain, HARDY_PLAIN, TERM=dumb, or a terminal session that fails to start.

Artifact contract

Formal dimension

Kernel verified · verified modulo explicit paper assumptions · partially formalized · not formalized.

Informal dimension

No gaps detected, with assessment provenance · known gaps listed · not assessed.

Lean acceptance is evidence for the formal claim. A compiled document is not. The statement connects the artifacts, and Hardy reports partial work rather than silently changing the theorem.

Feature horizon

Now · implemented Interactive slice

A durable chat, direct Lean and LaTeX feedback, linked names, approved assumptions, and saved artifacts. The one-shot proof loop remains a smoke path. Next, record a real acceptance run and pin its toolchains.

Next Honest experiments

Faithfulness and axiom audits, budgets, evaluation provenance, critique/repair, and literature-backed citations.

Later Breadth & hardening

Alternative runtimes, advanced search, assumed papers, retrieval, memory, warm workers, and restored isolation.

Trust boundary

The kernel is the formal authority, subject to its audited axiom set. The naming manifest connects Lean and LaTeX for later review but does not prove faithfulness. User-approved axioms are visible additions to trust. Until confinement is restored, generated Lean and TeX, downloaded archives, and computer algebra cells and their helper processes must all be treated as unsafe and run only in disposable environments.
