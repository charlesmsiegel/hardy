The complete design map

Hardy

A model-agnostic theorem-proving harness where language models propose, Lean verifies, and the harness preserves an honest account of what succeeded.

Interactive experiment implemented. Running hardy opens a durable mathematical conversation backed by direct Lean and LaTeX tools, a linked naming manifest, and explicit human approval for assumptions. The old sandbox remains absent; use only trusted output in a disposable environment. The real model + pinned toolchain acceptance runs are recorded under acceptance/recorded/ and rechecked without a model by hardy accept --recorded.

The core loop

1 · RequestAn informal claim, Lean theorem, or proof to inspect.
2 · OrchestrateChoose a workflow and strategy; enforce budgets and stopping rules.
3 · ExperimentThe model calls narrow tools and revises from structured Lean feedback.
4 · Verify & reportThe kernel checks formal work; Hardy saves artifacts, grades, and trajectory.

Model runtime

Claude through the Claude Code agent SDK, authenticated by subscription rather than an API key. Hardy's tools run in-process, so the harness still performs every check and write, but the SDK owns the turn loop, and with it the compaction of a long session — what the context keeps is decided invisibly and unrecorded — see issue #23. An opt-in api backend calls the Messages API directly and runs that loop in Hardy instead: it counts its own turns, keeps its own wall clock, holds the conversation as a list rather than a provider thread, and may decline a provider call partway through an exchange — the decision point a token budget or a mid-conversation ladder would need, and what lets hardy batch end a run at the submission it keeps rather than pay for a turn whose only effect could be to replace the proof the artifacts already carry. The cheap Lean closers are not that: hardy batch --closers tries its ladder before any runtime is built, so it works on every backend and a subscription user needs no API key for it. It needs an API key rather than a subscription, so which transport carried a run is recorded as part of that run's identity. Compaction is Hardy's there too: the summary is assembled from session.json, the Lean tree and the recorded tool results rather than narrated by a model, so it can be checked against them; the cut never separates a tool call from its result; and what was summarised, where the kept messages start and what the summary said all go into transcript.jsonl. /status --full prints the same summary at any time. On the subscription backends /model switches models without losing the provider thread, and --fresh-thread starts a session on a new one, discarding only the machine-local thread id and recording the change in the transcript while the workspace, its record and the spend ledger continue. The api backend has no provider thread to keep or discard: /model hands the conversation to the replacement runtime, --fresh-thread has nothing to do, and the conversation ends with the process either way. The user’s own Claude Code settings and CLAUDE.md are not inherited; what replaces them is the project’s own AGENTS.md (or HARDY.md) at the project root and nowhere above it, bounded, recorded in full in the transcript, and rendered as context that Hardy’s constraints outrank. Graded runs read no such file.

Tool layer

Bounded verbs for Lean, goals, lemmas, holes, papers, citations, and writeups.

Lean interaction

Direct invocation first; later persistent sessions, pools, snapshots, and cheap automation. hardy latency times the fixed import Mathlib prelude and reports the share a warm pool would recover — every call's prelude except the one each worker pays on its first — so that “later” is decided by a measurement rather than by appetite.

Computer algebra

A persistent kernel — SymPy by default, Singular or Macaulay2 when configured — so the model can compute before it guesses. Replay rebuilds state after a kernel dies and checks that an exported script and notebook reproduce the session; the script is then run as a subprocess, because replaying cells is not evidence about the file. What a cell printed is not what a cell did, so the default kernel also fingerprints its namespace after every cell and a rebuild compares that too — walking the object graph rather than printing it, because a = []; b = a and a = []; b = [] render alike and behave differently — and the published script, run at the path it was published to, brackets its own transcript, so the comparison is equality rather than a guess about which lines the interpreter added — and says at shutdown whether it reached its own last line, because exiting cleanly is not the same as having finished. No computation is evidence: the verifier never reads any of it.

Environment

One installer per OS takes a clean Linux, macOS, or Windows machine to a working hardy: Python, lake via elan, a shared Mathlib project, pdflatex, and a config file that hardy doctor then verifies. WSL is never required.

Terminal (hardy.app.tui)

On a TTY, a real prompt_toolkit shell: ghost-text command completion, a /model selector, a reply drawn as the model writes it with each tool call named while it runs, and Esc that cancels a turn — the model stops, no further tool call runs, and the Lean, LaTeX, or computer algebra child already running is interrupted rather than left to its timeout, with a second Esc escalating from interrupt to kill. The turn ends on every backend, but only the subscription SDKs can interrupt the provider itself: an api request already in flight runs to its answer and is billed for, and that answer is recorded as discarded rather than shown. An export’s own replay kernel and script run in a session of their own and keep only their own limits. Falls back to a line-based session with the same commands — no TTY, --plain, HARDY_PLAIN, TERM=dumb, or a terminal session that fails to start. The staged prove workflow is reachable here as /prove — same workflow, same frozen claim and same independent read, asked through this terminal instead of through blocking console prompts. /status --full prints the workspace’s own summary of the session, assembled from the record, the Lean tree and the transcript rather than narrated by the model, and carrying no spend. /export writes one self-contained HTML account of the session — conversation, sources, verdicts, registry, approved assumptions with provenance, spend, the project instructions the model was given, the points where its memory was reset, the shared Lean from .hardy/lean its theorems actually import (the closure, not every module on the machine), and identities beside the settings that decided what the session could find out — rendering a kernel-verified theorem, one checked given an approved axiom, and a sentence from the conversation as three visibly different things, with known credential shapes removed and the page saying that this is a filter rather than a proof. A project may add its own commands as .hardy/prompts/<name>.md; the transcript records the expansion rather than the /name, and such a template is input rather than instruction, so it never moves the recorded prompt-set hash.

Core A and B: shared project primitives

Reusable mathematical project operations preserve exact identities across restarts and retain missing semantic prerequisites as typed obligations. Their production adapters and project-aware CLI/UI wiring remain unconfigured. See the canonical roadmap for ownership and scheduling.

Implemented Atomic ledger and exact graph

Immutable contracts describe items, contexts, bindings, obligations, scopes, evidence and publication. An append-only project ledger/, separate from session.json, commits atomic transactions under a writer lock and validates exact history on restart. Pure graph queries expose dependencies, reverse closure, paths, cycles, blockers, context ancestry and minimal recorded declaration/convention closure. Stale writers, corrupt events and sequence gaps are refused; child contexts preserve earlier results.

Implemented Policy and derived views

Acceptance defaults to denial unless injected capability readers authenticate exact evidence and decisions, including after restart. Local hypotheses do not widen trust, and transport needs justification for its particular mapping. Views report research/context, representations, obligations, trust, citation/formalization coverage, stale artifacts and publication readiness. Recorded status alone is not proof.

Implemented Context and representation operations

Model-normalized declarations, hypotheses, choices, aliases and conventions form immutable context branches. Ancestor activation and sibling forks preserve history; minimal recorded closure feeds A2 and optional materialization retains typed prerequisites. Representation resolution composes injected local/Mathlib search, structured model decisions and optional materialization with or without a target theorem. Model/configuration identity, reasons, assumptions and exact interprets/uses/refines links remain inspectable. A stronger plan gets a new identity; mathematical adequacy remains the model's assessment.

Implemented Formalization and admission seams

Standalone Prove reuses formalization; optional contextual callers bind exact source records and generated binder origins into the frozen identity while legacy context-free hashes remain stable. Shared admission policy checks request category, scope, source and probes; adapters retain confirmation, quarantine, persistence and publication.

Implemented Strategy and manuscript contracts

A bounded strategy returns an attempt or submission without assigning a formal grade. The manuscript inventory reports literal sections, conservative blocks, labels, citations, spans and digests from supplied text only; it never reads paths, executes TeX, expands macros, or judges mathematics.

Implemented Core C prerequisite acquisition

Search-first classification, definition acquisition before explicit opaque proposals, exact literature comparison and admission requests, and minimal required interface fields share the ledger. Recursive resolution checkpoints child work, resumes parents only after authenticated completion, and preserves unresolved cycles, missing resolvers and exhausted bounds. Revoked child evidence invalidates parent completion.

Implemented API Iterative and sketch strategies

Staged Prove delegates its existing repair loop to the shared strategy. Sketches use independent local lemmas, cheap closers, iterative fallback, shared verification/time ceilings and exact final parent verification. Each attempt uses a fresh run store; open holes and trajectories persist. Runtime tool gates remain caller-owned. No sketch CLI, live model result or execution isolation is claimed.

Implemented API Core D mathematical workflows

Research schedules shared formalization, prerequisites and target operations. Explore persists concepts, setup, contexts, goals and approaches. Critique records typed findings with explicit review coverage; Repair retains the stored frozen claim through guarded saving and dependent rechecks. Referee binds manuscript spans to exact claims and reports coverage, unresolved work and external contracts. Structural checks do not impersonate an adversarial reviewer.

Implemented API Publication planning and assembly

Plans select exact mathematics, minimal local context, examples, citations and recorded prose, with missing/stale exposition explicit. A fresh guarded bundle feeds existing mechanical document compilation. Human prose is not silently generated or replaced; compilation does not establish mathematics.

Implemented Core F proof search

Ranked textual candidates retain exact sources and Lean feedback. Shared atomic check allocation and deadlines prevent retries or branches resetting budgets. Staged Claude exposes best-first; independent race and escalation APIs reserve final verification, preserve partials and report losing-branch spend. Provider contexts and mathematical approaches remain distinct.

Implemented X1 evaluation comparison

Read-only comparisons authenticate recorded boards, pair exact problem/repeat slots and show intended versus uncontrolled differences. Invalid or missing rows and partial usage stay visible; canonical review cost is separate. Recorded controls and deterministic fixtures do not establish model improvement.

Later: application integration Production adapters

Core A-D have hermetic persistence and owner-composition tests. Applications supply named capability readers, model/search and guarded-save operations; terminal wiring and Core E human-guided trials are deferred. No new live-model performance result or execution isolation is claimed.

Hardening acceptance

Completed S0 policy and S3 operational audit

The disposable Windows baseline permits outside reads, outside writes and loopback connections. Process limits must be finite and valid; compiler capture is bounded, overflow stops promptly, and truncated probes cannot become successful environment observations. TeX diagnostics disclose overflow. Existing guarded writes, cancellation and export filtering remain distinct controls.

Unaccepted S1 confinement and S2 independent audit

The tested native Windows capabilities do not establish aggregate scratch byte and file-count quotas. No complete confinement boundary or trusted independent axiom verifier has been demonstrated. Generated Lean, TeX, computer algebra and helper processes remain unconfined. See the policy and capability findings and hardening verification report.

Artifact contract

Formal dimension

Kernel verified · verified modulo explicit paper assumptions · partially formalized · not formalized.

Informal dimension

No gaps detected, with assessment provenance · known gaps listed · not assessed.

Lean acceptance is evidence for the formal claim. A compiled document is not. The statement connects the artifacts, and Hardy reports partial work rather than silently changing the theorem.

A kernel-verified grade names the record its verification hash is taken over — frozen claim, elaborated Lean source, reported axioms, toolchain — so a reader can rebuild the record from the run directory and recompute the hash. The hash is derived, never declared. It still cannot show that Lean ran: the axiom list has no second witness on disk.

Feature horizon

Now · implemented Interactive slice

A durable chat, direct Lean and LaTeX feedback, linked names, approved assumptions, and saved artifacts. A folder holds several problems side by side, each with its own record, transcript, approved assumptions and Lean namespace; /project list, /project switch and /project new move between them in the process already running, rebuilding what belongs to a problem and keeping the pinned Lake project and the Mathlib environment, which belong to the folder. Both artifacts are trees: Lean modules import each other through an olean directory Hardy builds and puts on LEAN_PATH, and a save that would break a dependent is refused whole. An existing pile of Lean and TeX is weeded in through /import, human-directed with no model tool: triage elaborates every pile file and sorts the lot — compiles clean, with holes, broken, not mathematics — writing nothing, and promoting a file routes it through the same gates and audit an authored save gets (only the authorship ratchet is skipped), recorded as arrived-from-outside under the digest of its bytes. Every compile stamps page one with what the document is: how many theorems Lean checked, what was assumed, what is asserted on neither footing, and which saved statements a single automation call closes outright, each named with its tactic — and a change to anything the stamp would overstate makes the writeup stale. A saved theorem owes a writeup once it closes, before another may be added — one still resting on a hole owes none of it yet, so skeletons accumulate without a word of LaTeX between them, and theorem is reserved to a name record_name has already mapped, which leaves lemma free for every intermediate step. The writeup owes its reader the Lean: the label the compiler really made, and the theorem's exact statement quoted verbatim in the document the root pulls in, with everything the work assumes stated in an appendix in both languages. Calling anything finished is a tool call refused until all of that holds, and at the end of every turn Hardy draws what the workspace still owes under its own name, computed from the two trees rather than from anything the model said. and every exported theorem and lemma that a rebuilt module's source declares is audited for what it actually depends on before anything is written — private scaffolding is out of scope, and so is a result a macro generates without a literal declaration — a verdict covers the declarations it names, not everything a module exports. A verdict carries the toolchain and project that produced it, and one recorded under another is reported as no longer established rather than as current. The one-shot proof loop remains a smoke path. While it proves, a model can ask rank_premises which declarations are worth looking at for a goal, fusing a declaration-name index over the pinned Mathlib sources with Loogle — Lean's own #find was dropped after being measured never to answer on the pinned toolchain; retrieval spends a metered budget, and every ranking names each source it asked under a digest a reader can recompute and says whether the order can be replayed — the pinned index can, the public Loogle cannot. The session also carries what it has spent: the cost and token usage the provider reports for each exchange, accumulated in .local/state.json so reopening a workspace continues the total, abbreviated on the session rule and broken out in /status — reported, never estimated, and shown as unreported rather than as zero when a backend says nothing. The session also reads the literature under the same rule the rest of it lives by, that a claim is worth what its record is worth: search_papers finds leads, fetch_paper pins one paper at one version and stores it with a digest that is checked again on every read, read_paper serves a bounded window of what was stored, and cite_paper writes it into the problem's one canonical bibliography — the only code path that may write it — and hands back a cite key derived from the paper rather than from the order it arrived in. A citation is possible only for a paper Hardy actually fetched, because the tool takes an identifier and nothing else, so there is no argument that puts a remembered reference in the document — and the writeup may not declare references itself either, since an invented \bibitem resolves exactly as well as a real one: every entry the compiler really made, read out of the .aux it wrote so that macro expansion counts the same as a literal command, must be a key cite_paper recorded, and the generated reference list is Hardy's file rather than the workspace's, generated to compile — escaped, folded to lines a TeX input buffer can hold, and reduced to characters pdfLaTeX can set — since it is the one file in the tree a model may not repair; fetch_source then downloads that version’s LaTeX bundle and unpacks it as though it meant harm — member paths normalised, every symlink and hardlink refused rather than skipped, file and byte quotas enforced on the decompressed stream, extraction staged in a temporary directory that lands with one rename, and the archive kept beside the tree it unpacked to so that its digest can be checked on every read — and nothing in it is ever executed or compiled, which bounds what an archive can do to the filesystem without being a sandbox. Once a source is held, list_statements shows everything the paper states and assume_statement mints one of those as a Lean axiom in Papers.<CiteKey> — after Hardy elaborates the proposed Lean, searches for a counterexample to it, and an independent reader with no tools and no session history compares it against the paper’s own sentence; a statement that reader will not accept is quarantined, recorded and refused by the save gate rather than admitted with a warning. On the document side a compile is no longer judged on its exit status alone: LaTeX resolves a missing \ref to ?? and a missing \cite to [?] and exits successfully, so the compiler is run until it stops asking for another pass and its log is then read — an undefined reference, an undefined citation, or a label defined twice refuses the save and names what did not resolve, as does a document still asking to be run again after the last pass, whose numbers have not settled; a label nothing points at is reported rather than refused, since the completion gate requires labels nothing need reference. The acceptance runs are recorded: both surfaces reach verified on a theorem that needs an intermediate fact and a found Mathlib lemma, a false statement is refused rather than graded, and a starved budget ends as Hardy’s own wall-clock limit — each record naming the Lean, Mathlib and Tectonic it ran against by revision, asked of the machine rather than written as constants.

Now · implemented Evaluation set

A tiered, classified corpus (corpus/, twenty statements, five false twins) with a mechanically measured automation floor. The corpus is a standalone CC-BY-4.0 dataset: entries sharded by MSC2020 2-digit class, holding statements only — no tier, no solve rate, nothing derived — with a permanent id registry and a release gated by a manifest digest the changelog head binds. hardy evals corpus check reports every mechanical objection; hardy evals corpus report gives coverage by reporting group, status, difficulty and source; hardy evals corpus release stamps a new version across the shards and writes the changelog section binding its manifest digest; and hardy evals corpus serve opens a local authoring view that re-reads the corpus from disk on every request, so an entry added in an editor appears on the next refresh. hardy evals baseline sweeps a committed tactic set — anonymous examples carrying each entry's own binders, then a named theorem alone — against every canonical statement and tiers it by how much a plain tactic already closes, by heartbeats rather than wall time. hardy evals run --label scores a model above that floor, batch or staged, and writes a scoreboard under evals/scoreboards/<label>/; a staged solve also passes an independent reader comparing the model's frozen Lean signature against the canonical declaration. hardy evals check re-derives every figure in a committed scoreboard from its run directories and the corpus and tier file it names by digest, as hardy accept --recorded does for the acceptance runs, which need nothing but the run itself. A scoreboard is one condition run on one day, not a moving average, and the runner drives the Claude backend only. src/hardy/corpus/ holds content schemas, the loader, taxonomy and content identity; src/hardy/evals/ holds experimental contracts, measurement identity, the sweep, set runner and validator.

Trust boundary

The kernel is the formal authority, and Hardy grades on the axiom set Lean reports rather than on an exit code. sorryAx is a hole and cannot be approved — fatal to a grade, though not to an interactive save, which keeps the unfinished proof and reports every theorem resting on one as open until it closes; any other non-standard axiom is refused unattended by prove and batch, and refused interactively until a human approves it. A report that is missing, duplicated, or unreadable is a refusal rather than a pass. The audit is elaborated by an environment the audited source could itself have extended, so it establishes that an artifact is not accidentally unsound and not that it is not adversarial. The naming manifest connects Lean and LaTeX for later review but does not prove faithfulness; the frozen claim is read back before any proof search by an independent model that is given the user’s words and the Lean signature alone — not the conversation that wrote them — and a translation it will not accept, or a reader that cannot be reached, stops the run rather than proceeding, with the verdict recorded beside the claim. That reader holds no tools on the Claude backend, which is what makes the separation real there; under --backend codex it is not established at all, because that SDK’s read-only sandbox permits reads anywhere and offers no readable-root control, so the reader could reach the run’s own artifacts by absolute path. Each runtime reports what its isolation is worth and every verdict, manifest and compiled paper records it, so a run whose independence was never established says so rather than reading like one where it was. User-approved axioms are visible additions to trust — but the approval binds the axiom's name: Hardy records the statement a human was shown without asking Lean whether the imported declaration actually says that, and a verified modulo result must now disclose its assumptions in the document's appendix, in both Lean and prose, before it can be reported at all. A staged run may declare the axioms it is allowed to stand on; each is checked for an obvious counterexample before any proving begins, is rendered into the source the independent verifier elaborates rather than read out of the run's workspace, and a proof that used one is graded verified modulo — a third grade, with the manifest and the compiled document naming exactly the assumptions Lean reported the proof depends on rather than the ones that were permitted, and an axiom nobody declared still refusing the proof. Before that approval is even asked for, request_assumption is refused outright unless a search for the result was actually tried since the last request, Hardy elaborates the proposed axiom itself and runs it through two fail-closed probes — whether standard tactics close it outright, making it a theorem rather than an assumption, and whether the conclusion survives with its hypotheses stripped, warning that the assumption may be vacuous — and both probes read Lean's diagnostics by line, never crediting an error outside the lines they wrote as a tactic having closed the goal. The same tactic ladder is run against every theorem a save introduces or restates, with the opposite consequence: a statement one tactic closes is disclosed — on the save's own result, in the document's banner, in /status and read_workspace — rather than refused, because a lemma that falls to simp is still a lemma while a vacuous statement under a grand name must not be counted as machine-checked silently; the verdict expires with the statement and the toolchain it was established under. The human sees what was searched, what Lean found, and, on a resubmitted name, the statement an earlier request under it was refused or declined with, all recorded to the transcript as an assumption_prompt event before the decision is asked for. The document gate reads what is formally asserted: a theorem environment owes a label backed by saved Lean or an approved assumption, while a claim placed in prose or in a lemma environment owes nothing, by design — the page-one banner’s counts disclose how much of the document is backed at all, never which claim is not. There is no extension surface, and the boundary any future one must respect is fixed in advance: an extension may observe, propose, and render, never verify, audit, or write the record — the audit, the verifier, the transcript, the manifest and every refusal stay closed, and a user’s own text is input recorded as input, never evidence. Until confinement is restored, generated Lean and TeX, downloaded archives, and computer algebra cells and their helper processes must all be treated as unsafe and run only in disposable environments.
