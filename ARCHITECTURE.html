The complete design map

Hardy

A model-agnostic theorem-proving harness where language models propose, Lean verifies, and the harness preserves an honest account of what succeeded.

Interactive experiment implemented. Running hardy opens a durable mathematical conversation backed by direct Lean and LaTeX tools, a linked naming manifest, and explicit human approval for assumptions. The old sandbox remains absent; use only trusted output in a disposable environment. A real model + pinned toolchain acceptance run is still outstanding.

The core loop

1 · RequestAn informal claim, Lean theorem, or proof to inspect.
2 · OrchestrateChoose a workflow and strategy; enforce budgets and stopping rules.
3 · ExperimentThe model calls narrow tools and revises from structured Lean feedback.
4 · Verify & reportThe kernel checks formal work; Hardy saves artifacts, grades, and trajectory.

System layers

Workflow & strategy

Phases, retries, budgets, fixed points, and pluggable search from iterative repair to parallel attempts.

Model runtime

Claude through the Claude Code agent SDK, authenticated by subscription rather than an API key. Hardy's tools run in-process, so the harness still performs every check and write, but the SDK owns the turn loop — see issue #23. /model switches models without losing the provider thread.

Tool layer

Bounded verbs for Lean, goals, lemmas, holes, papers, citations, and writeups.

Lean interaction

Direct invocation first; later persistent sessions, pools, snapshots, and cheap automation. hardy latency times the fixed import Mathlib prelude and reports the share a warm pool would recover — every call's prelude except the one each worker pays on its first — so that “later” is decided by a measurement rather than by appetite.

Computer algebra

A persistent kernel — SymPy by default, Singular or Macaulay2 when configured — so the model can compute before it guesses. Replay rebuilds state after a kernel dies and checks that an exported script and notebook reproduce the session; the script is then run as a subprocess, because replaying cells is not evidence about the file. No computation is evidence: the verifier never reads any of it.

Knowledge

Versioned literature, premise retrieval, assumed-paper libraries, and contamination-aware memory.

Evidence

Trajectories, anti-cheat audits, immutable provenance, fixed benchmarks, and equal-budget comparisons.

Environment

One installer per OS takes a clean Linux, macOS, or Windows machine to a working hardy: Python, lake via elan, a shared Mathlib project, pdflatex, and a config file that hardy doctor then verifies. WSL is never required.

Terminal (hardy.tui)

On a TTY, a real prompt_toolkit shell: ghost-text command completion, a /model selector, a reply drawn as the model writes it with each tool call named while it runs, and Esc that cancels a turn — the model stops, no further tool call runs, and the Lean, LaTeX, or computer algebra child already running is interrupted rather than left to its timeout, with a second Esc escalating from interrupt to kill. An export’s own replay kernel and script run in a session of their own and keep only their own limits. Falls back to a line-based session with the same commands — no TTY, --plain, HARDY_PLAIN, TERM=dumb, or a terminal session that fails to start.

Artifact contract

Formal dimension

Kernel verified · verified modulo explicit paper assumptions · partially formalized · not formalized.

Informal dimension

No gaps detected, with assessment provenance · known gaps listed · not assessed.

Lean acceptance is evidence for the formal claim. A compiled document is not. The statement connects the artifacts, and Hardy reports partial work rather than silently changing the theorem.

A kernel-verified grade names the record its verification hash is taken over — frozen claim, elaborated Lean source, reported axioms, toolchain — so a reader can rebuild the record from the run directory and recompute the hash. The hash is derived, never declared. It still cannot show that Lean ran: the axiom list has no second witness on disk.

Feature horizon

Now · implemented Interactive slice

A durable chat, direct Lean and LaTeX feedback, linked names, approved assumptions, and saved artifacts. Both artifacts are trees: Lean modules import each other through an olean directory Hardy builds and puts on LEAN_PATH, and a save that would break a dependent is refused whole. A saved theorem owes a writeup before another may be added, and every exported theorem and lemma that a rebuilt module's source declares is audited for what it actually depends on before anything is written — private scaffolding is out of scope, and so is a result a macro generates without a literal declaration — a verdict covers the declarations it names, not everything a module exports. A verdict carries the toolchain and project that produced it, and one recorded under another is reported as no longer established rather than as current. The one-shot proof loop remains a smoke path. While it proves, a model can ask rank_premises which declarations are worth looking at for a goal, fusing Lean's own #find with Loogle; retrieval spends a metered budget, and every ranking names each source it asked under a digest a reader can recompute and says whether the order can be replayed — the pinned environment can, the public Loogle cannot. The session also carries what it has spent: the cost and token usage the provider reports for each exchange, accumulated in session.json so reopening a workspace continues the total, abbreviated on the session rule and broken out in /status — reported, never estimated, and shown as unreported rather than as zero when a backend says nothing. Trust boundary

The kernel is the formal authority, and Hardy grades on the axiom set Lean reports rather than on an exit code. sorryAx is fatal and cannot be approved; any other non-standard axiom is refused unattended by prove and batch, and refused interactively until a human approves it. A report that is missing, duplicated, or unreadable is a refusal rather than a pass. The audit is elaborated by an environment the audited source could itself have extended, so it establishes that an artifact is not accidentally unsound and not that it is not adversarial. The naming manifest connects Lean and LaTeX for later review but does not prove faithfulness. User-approved axioms are visible additions to trust — but the approval binds the axiom's name: Hardy records the statement a human was shown without asking Lean whether the imported declaration actually says that, and a verified modulo Lean save does not yet require the writeup to disclose the assumption. Until confinement is restored, generated Lean and TeX, downloaded archives, and computer algebra cells and their helper processes must all be treated as unsafe and run only in disposable environments.
